# 2026-11-17 (Dipanshu)

## Session - Phase 1 gap APIs (issues, chat, feedback, surveys, push, safety, profile) on branch `dipanshu/rydo-api`
**Why:** The Phase 1 feature PDF, the project specification and the technical blueprint list features the API did not have yet. The owner asked for everything except payments and pricing (everything stays free for now).

**What was done (backend only: `services/api`, `packages/shared`)**
- Migration `20261117100000_engagement_apis` (additive): messages get `rider_membership_id` + `read_at`; emergency_contacts get `email`; vehicles get `car_type` (HATCHBACK/SEDAN/SUV); new tables `feedback`, `surveys`, `survey_responses`.
- Issue reports: `/me/issues`, `/admin/issues` (open → in progress → resolved, reopen allowed, reporter notified, admins notified at once by in-app + push + email).
- Ride chat: `/rides/:id/chat…` one thread per (ride, rider) between the driver and a confirmed rider; Socket.IO room `chat:<ride>:<rider>` (`chat.subscribe`, `chat.message`, `chat.read`); archived when the ride ends; blocks respected; unread badge endpoint.
- Feedback form, admin feedback list/review/CSV, feedback insights (rating trend, categories, issue resolution times, keyword themes).
- Surveys (draft → publish to everyone or a segment → close), anonymous results with response rate; employee list/answer.
- Announcements to everyone or a segment (history comes from the activity log).
- Push: device registration, `PushAdapter` (Firebase HTTP v1 adapter with a signed service-account token, or a logger when FCM_* is empty). Every notification now also pushes; dead tokens are removed; push never fails the action.
- Safety: emergency contacts (max 5), blocks API (search already honoured blocks), email the live-trip link to chosen contacts.
- Profile: photo upload via signed link, `/me/profile` with rating average + comments, `/members/:id/card`, phone on `PATCH /me`.
- Search: filters `carTypes` and `ac`; vehicles accept `carType`.
- Reference for frontend developers: `services/api/ENGAGEMENT_API.md`.
- Tests: new files issues, chat, feedback (with surveys and announcements), safety, push; each includes cross-company checks. Shared fixture `test/world.ts`.

**Decisions**
- Chat is private to the two people: admins cannot read chats (spec says admins only with an operational need; none defined yet).
- Survey results are anonymous. Announcement history is stored in the activity log (no extra table).
- Push uses Firebase over plain HTTPS (no Firebase package, since installing packages was not allowed in this session).
- Not built on purpose: payments/pricing (owner), PDF reports (needs a PDF package), Safety Officer as a separate role (Ops admin covers it), SMS to emergency contacts (only email is set up).

**Problems hit & how fixed**
- `prisma generate` cannot replace the engine file while the API runs (Windows lock). The type files still updated, so work continued; stop the API before the next schema change.
- A Google key was found in git history (first commit `ae5d5f0`, `services/api/.env.test`); the later commit removed it from the file but not from history. Rotate that key in Google Cloud.
