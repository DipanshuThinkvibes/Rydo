## Session - Self sign-up with employee details, ID proof and "Continue with Google"
**Why:** Owner asked for a sign-up that checks the company domain, collects employee name, employee ID, work email, ID proof (type, number, photo), manager name and ID, contact number, and offers Continue with Google.

**API (services/api, packages/shared)**
- Migration `20261119100000_employee_signup`: `users.google_sub` (unique); memberships get `manager_name`, `manager_employee_code`, `id_proof_type`, `id_proof_number`, `id_proof_key`, `signed_up_at` (employee ID uses the existing `employee_code`).
- `POST /auth/signup/check` {email} → {registered, companyName}.
- `POST /auth/signup` multipart (fields + `idProof` photo/PDF ≤5 MB): email proven by the 6-digit code (`/auth/otp/request`) or a Google ID token for the same verified email; company must own the domain; one sign-up per email; employee ID unique per company; creates/updates the user and a PENDING RIDER membership; ID photo stored privately; returns a session.
- `POST /auth/google` {idToken}: known person → session (links google_sub); new person on a registered domain → {needsSignup, email, name, companyName}; other domains → COMPANY_NOT_ON_RYDO.
- `IdentityAdapter` / `GoogleIdentityAdapter` (Google tokeninfo over HTTPS, audience = `GOOGLE_OAUTH_CLIENT_IDS`); tests use `FakeIdentity` (`google:<email>:<sub>` tokens).
- `GET /admin/members` now returns employeeId, phone, manager, ID type/number, hasIdProof; `GET /admin/members/:id/id-proof-url` (ORG/HR, 5-min link, audited `ID_PROOF_VIEWED`).
- Shared: `ID_PROOF_TYPES/LABELS`, `signupCheckSchema`, `signupSchema` (per-type ID number formats), `googleSignInSchema`, `GoogleSignInResult`.
- Tests: `test/signup.e2e-spec.ts` (domain check, masked Aadhaar, private photo, duplicates, wrong code, bad ID, missing photo, Google new/known/mismatch/unverified, HR view + cross-company + rider refused).

**Mobile (apps/mobile)**
- `/signup`: work email → domain check + code sent → form (all fields, ID type chips, photo from camera/gallery, password, code) validated with the shared schema → account → "Waiting for HR approval".
- Sign-in: "Continue with Google" (expo-auth-session; hidden until client ids are set) and "New to RYDO? Create an account"; Welcome has "Create an account" + "I already have an account".
- Admin → Employees shows the sign-up details and a "View ID proof" button.
- `lib/photo.ts` shared photo picker (driver documents and ID proof).

**Decisions**
- Aadhaar numbers stored masked (last 4 digits); other ID numbers in full; ID photo private (HR only, short-lived link, every view logged).
- Google token check over HTTPS behind an adapter instead of adding google-auth-library (no package installs; vendor rule).
