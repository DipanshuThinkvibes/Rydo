# 2026-11-18 (Anjali)

## Session - Mobile app screens from the RYDO Share prototype (`apps/mobile`)
**Why:** The owner shared `RYDO_Share_Mobile_Prototype.pdf` (14 screens) and asked for every screen to be built in this direction. The mobile app only had sign-in and a "waiting for HR" home.

**What was done (mobile only: `apps/mobile/src`; no API or shared changes)**
- Foundation: the API client now sends `x-org-id` (company routes failed from the phone before) and has `apiWithMeta`; the session exposes `active`, `roles`, `isAdmin`, `features`. New `lib/format.ts`, `lib/hooks.ts` (`useData` loads on focus and polls; `useLiveRide`), `lib/places.ts` (offices, Google place search via `/maps`, ride-search draft), `lib/safety.ts` (share link, SOS, open Google Maps), `lib/simulator.ts` (drive simulator), `lib/types.ts`.
- UI kit (`components/ui.tsx`, `icons.tsx`, `route-map.tsx`, `tab-bar.tsx`, `place-picker.tsx`, `stars.tsx`, `mode-switch.tsx`): chips, switch, avatar, PIN tiles, plate, stepper, sheet, action tiles; icons drawn with views; route map drawn with views (real route polyline and points on a stylised street grid).
- Screens (prototype page → route):
  1. Welcome → `/welcome`
  2. Home (map, Where to?, Office/Home shortcuts, next ride, plan your week) → `/`
  3. Plan your ride → `/plan`
  4. Rides found with match % and "why this match", filters, waitlist → `/results`
  5. Driver accepted / waiting for answer → `/requested`
  6-8. Pickup details with PIN → on the way (progress, long-stop check) → arrived with stats and rating → `/trip/[bookingId]`
  9. Ride chat with quick replies → `/chat/[rideId]/[riderId]` (`me` for the rider)
  10. Drive home: offering seats, next ride with Start trip, stats, publish, verified driver, new-request pop-up with countdown → `/drive`
  11. Driver trip: next pickup banner, Open in Google Maps, I've arrived, PIN check, no-show, complete, rate riders → `/driving/[rideId]`
  12. Publish a ride → `/publish`
  13. My commute (Office/WFH/Leave per day, auto-book, find rides for my week, home pickup) → `/commute`
  14. Admin (SOS acknowledge/resolve, to approve, rides today, open issues; employees, drivers with document links, issues) → `/admin`
  - Plus: report a problem → `/report` (uses `/me/issues`).
- Bottom tabs Home / Commute / Drive / Admin (Admin only for ORG/HR/OPS admins), built as plain stack screens with no animation.

**Decisions**
- No new packages (installs were blocked in this session): maps and icons are drawn with views; the map component keeps the same props so `react-native-maps` can replace it in one file.
- Live data is polled (ride every 4-5 s, chat every 4 s, lists every 10-30 s) instead of Socket.IO, because `socket.io-client` is not a mobile dependency and adding it would break `npm ci` until the lock file is updated.
- Prototype items with no API are left out, not faked: "Quiet ride" / "No smoking" preferences, Call buttons (masked calls are "Later"), "N colleagues driving now", detour minutes on requests, turn-by-turn text (the banner shows distance to the next stop instead).
- Driver GPS: the trip screen has a "Simulate drive" switch (same as the web simulator) until `expo-location` is added.
- Becoming a driver (vehicle + license/RC photos) stays on the web for now: needs `expo-image-picker`.

**Problems hit & how fixed**
- `packages/shared/dist` is older than `src` (no `engagement`, no `ac` filter). Typecheck was run against `src` with a temporary tsconfig; run `npm run build -w @rydo/shared` before starting Expo.
- Workspace links (`node_modules/@rydo/*`) are not visible from the Linux shell, so the plain `npm run typecheck -w @rydo/mobile` could not be used there; run it on Windows.

**Next time start here**
Not committed. On Windows: `npm run build -w @rydo/shared`, `npm run typecheck -w @rydo/mobile`, `npx expo start` and click through every screen with seeded users (rider, driver, HR). Then add `expo-location` (background GPS), `react-native-maps`, `expo-image-picker` (driver documents, profile photo), `expo-notifications` (push via `/me/devices`) and `socket.io-client`.
